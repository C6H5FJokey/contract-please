# 交涉框架与编剧指南

台词、选项、材料、可举证的主张和改稿都写在同一份剧本文件。改一句话或分一条路，从 [泊石展务剧本](../web/dist/chapters/boshi.js) 入手。浏览器直接加载这些数据，保存后刷新即可读新文本。

| 文件 | 职责 |
| --- | --- |
| [chapters/](../web/dist/chapters/index.js) | 内容入口。每份剧本定义自己的角色、材料、交涉路线、修改和结局。 |
| [negotiation.js](../web/dist/negotiation.js) | 运行剧本、选择、举证、耐心、检查点和续关，产出交涉事件。 |
| [dossier.js](../web/dist/dossier.js) | 管理已公开的材料及其版本，定位引用，生成书面改稿。 |
| [app.js](../web/dist/app.js) / [playback.js](../web/dist/playback.js) | 把同一批事件呈现成聊天。处理读档、圈选、逐字显示、附件延时和点按跳过。 |

`openNegotiation(chapter, saved?)` 是界面和测试共用的入口。用 `view()` 读取可见文件、记录和本轮可用操作，用 `act(command)` 从合同开启话题（`openTopic`）、结束本轮（`endTopic`）、提交选择、确认一段引用（`cite`）、回到之前的一段（`revise`）、退回话题、续关或结案。它返回本次新增的事件，界面按顺序播放。打字速度不会改变事件内容，也不会推进玩家尚未选择的分支。

## 改剧本

1. 先写清楚四件事：玩家想拿到什么，对方想让他接受什么，对方掌握什么，权限到哪儿为止。
2. 在 `documents` 里为每份材料和可单独引用的原句起稳定 ID。只把开局应拿到的材料放进 `initialFiles`，其余在谈话节点的 `files` 发出。文件已有时，可用 `revisit` 写一句针对已发材料的回复。
3. 在 `nodes` 写角色说的话（`say`）和玩家可选的回复（`choices`）。选项通过 `go` 连到下一段。节点也可以用 `go` 自动接上下一段，用于发完附件回桌或承接连续台词。`ifOpen` 可以在相关改稿已完成时隐藏重复选项。
4. 对方暴露可反驳的主张时，用 `proof` 代替普通选项。`steps` 为每一段待确认引用写一句主角的内心话，运行时会加括号。确认最后一段才判定。用 `accepts` 列出能证明矛盾的 `文档ID.原句ID` 和主角说出口的具体反驳（`say`）。当一段原文直接反驳对方刚才的话时，用 `anchor: "reply"` 把对方最后一句也放入记录。用 `mistakes` 写常见误读的答复，用 `defer` 和 `back` 写怎么退回话题。接受的组合不要求按选中顺序排列，旧稿中已被替换的句子会被指出。
5. 双方实际陷入僵局的节点用 `deadlock` 指定退回路径，扣耐心由框架处理。对方愿意让步后，先谈清楚书面改法，再进入有 `amend` 的节点。改稿定义列出正文和附件分别替换哪些原句，两份文件都会保留旧版。
6. 玩家签署或离开时使用 `endings`，零耐心的婉拒和继续台词来自 `refusal`。复盘按每项修改的 `edited`、`open` 和 `lesson` 显示这次实际谈下来的结果。

主合同正文的每个章节有独立 `id`，它在 `review.topics` 里对应一个话题。话题的 `player` 是主角开口说的话，`start` 是对方接话的节点。`review.node` 是等玩家读合同和选条款的节点。正常解释、玩家搁置和发完改稿都可回到这里。`amendments` 中有任一改稿完成后，话题标为「已改稿」，仍可打开。`followUps` 按顺序查找首个满足 `after` 改稿条件的入口，因此优先写最新改稿后的路线。每次进一步改稿应有独立 ID。添加第七个条款时，只需为它补一个话题，不用改交涉规则和界面。

例如，核对两份材料时，可以让主角先找当前约定，再找之前谈好的日期：

```js
discrepancy: {
  say: ["我说的日期和单据上一样。"],
  proof: {
    steps: ["我先找找，单据上写的是哪一天？", "我记得之前谈过日期，那条消息在哪儿？"],
    accepts: [{
      lines: ["receipt.date", "messages.date"],
      say: ["单据写的是周六，聊天里定的是周一。我周末到不了，能按我们原来谈的日期改吗？"],
    }],
    back: [{ go: "dates" }],
    defer: { text: "先沉默", thought: "我得再看看手里的单据。", say: ["行，你先看。"] },
    wrong: ["这两句说的不是同一笔。"],
    success: "discussRevision",
  },
}
```

每次迭代都应从开局走至少两条路径。特别检查：材料可以有线索价值但不能证明主张；没拿到关键材料也能安全退回；正确的举证先换来真实的反应和反报价，只有落纸才算改稿。同一份合同改多个地方时，分别试两种修改顺序。

## 接入下一份合同

新建剧本模块，给它自己的 `id`、`revision`、`contact`、`contract`、`documents`、`nodes`、`amendments`、`refusal` 和 `endings`，并加到 [剧本入口](../web/dist/chapters/index.js)。可用 `?chapter=剧本ID` 直接打开试玩。租房剧本可以把联系人换成中介或房东，把材料换成房屋清单、付款记录等，交涉规则和聊天界面沿用同一个入口。当前只注册了泊石展务。

每个剧本独立存档。存档保存已经执行的操作，读档时重放并恢复文件版本和聊天记录。改动已有选择、节点、判定或影响存档的文档内容后提高 `revision`，让旧存档开启新局。
