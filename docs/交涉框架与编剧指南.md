# 交涉框架与编剧指南

在 Inky 打开 [泊石展务的 story.ink](../content/boshi-pay/story.ink)，从开场后的「预览」菜单进入任一话题，编辑并试玩对白、内心话和选项。合同、附件、举证判定和改稿文字在同目录的 [chapter.ts](../content/boshi-pay/chapter.ts)。Inky 预览时会使用文件末尾的条件函数作为默认值。实际拿到文件或线索之后的分支，请进网页试玩。 [Inky 编辑器](https://github.com/inkle/inky)

## 写对白和选项

先写清玩家想争取什么，对方知道什么、想让玩家接受什么，以及对方能承诺到哪一步。用 Ink 的命名段落把对话分开。普通台词默认由对方说，`# player` 是主角说出口的话，`# thought` 是主角的内心活动，界面会加括号。玩家选择由游戏显示为主角台词。

```ink
=== ask_window ===
我想核对一下卧室窗户的状态。 # player
窗框我刚看过，没有水渍。
{has_clue("window"):
    + [我在窗边记下了一处情况。 # choice:show]
        -> window_claim
}
+ [我再回去看看。 # choice:later]
    -> desk
```

用 `+ [选项 # choice:ID]` 写可以重新选择的选项。同一组可见选项的 ID 要唯一，改台词时保留它们以便读档。`has_file("ID")` 和 `has_clue("ID")` 读取游戏状态。在 Inky 中可以临时把对应的备用函数返回值改成 `true`，预览获得材料后的分支，试玩完再恢复。

| Ink 标签 | 作用 |
| --- | --- |
| `# file:ID` | 发出指定附件。连续附件一起送达，游戏等待玩家确认读完。 |
| `# proof:ID` | 打开指定举证规则。用 `-> END` 结束该段，由玩家圈选原文。 |
| `# deadlock:ID` | 按指定检查点退回话题并扣耐心。用 `-> END` 结束该段。 |
| `# amend:ID` | 应用指定书面改稿，生成新版本并恢复一点耐心。 |
| `# desk` | 回到阅读和选话题的状态。 |

## 写文件和举证

在 `documents` 给每份材料和每条可引用原句指定稳定 ID。`initialFiles` 是开局就能看的文件。举证规则放在 `proofs`，用 `文档ID.原句ID` 写出正确组合和常见误读。`steps` 指向逐段出现的内心话，`accepts` 指向主角反驳和后续交涉，`mistakes` 与 `wrong` 指向对方的回应。`anchor: "reply"` 会把对方上一句台词附到对照记录中。

举证的 `back` 以及僵局的回退路线可以按已收材料选择检查点，最后保留一条无条件路线。用于内心话、错误反馈、退回和结案的短段落只写台词、内心话或发文件，末尾用 `-> END`。改稿在 `amendments` 定义。按文件 ID 和原句 ID 给出替换文本，同一句可以在后续不同改稿中再次替换。界面会保留修改前的版本和删除线。

## 接入话题和调查

`topics` 定义话题标签、进入 Ink 的段落和关联的改稿。用 `clauseTopics` 将主合同章节 ID 关联到话题 ID。话题改过后仍可开启，`followUps` 按顺序采用第一个已完成指定改稿的入口。

调查入口可参考 [窗户测试场景](../content/window-demo/chapter.ts)。`floorPlan.hotspots` 的坐标是相对于图片宽高的百分比，`observation` 是玩家点到位置时看到的结果。`files` 可发放用来举证的材料，`topic` 则允许玩家调查后主动开口。合同和调查点可以指向同一个话题。调查和开口分别存档。

新增剧本时，在 `content/` 新建目录并在 [剧本入口](../src/chapters.ts) 与[构建脚本](../tools/build.ts) 注册。两份现有剧本都示范了开场、结束话题、续关和签署所用的段落名称。正式构建发布泊石展务剧本，本地 `npm start` 可以通过 `?chapter=window-demo` 打开户型图测试。

在仓库根目录运行 `npm test` 检查类型、剧本引用、举证、续关和保存恢复。运行 `npm start` 完整试玩，修改剧本后重新构建。若更改已发布的选项 ID、段落路线或影响重放的内容，提升该剧本的 `revision`。
