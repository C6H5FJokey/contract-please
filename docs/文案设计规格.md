# 文案设计规格

《来，签合同》的文案服务于合同阅读与交涉，不以漂亮句子、法律术语或完整说明为优先。玩家应当能听出是谁在说、此刻想得到什么，以及哪句话仍然没有落到纸面上。

本规格适用于章节对白、玩家选项、主人公内心活动、举证反馈、改稿通知与结案文本。剧情结构、材料规则和 Ink 接口见 [《交涉框架与编剧指南》](交涉框架与编剧指南.md)；具体章节的设定仍以该章剧本规格为准。

## 一、文案目标

1. **像在场的人说的话。** 台词从眼前的谈判关系、利益和权限出发，不像编剧借角色之口解释系统。
2. **让表达承担交涉。** 每次开口至少完成一件事：问清事实、回避问题、索取材料、确认承诺、指出冲突、提出条件、作出让步或结束谈话。
3. **把判断留给玩家。** 提出异议时呈现事实与直觉，不提前公布证据答案；提交错误后才通过主人公反思给出引导。
4. **区分口头说法与书面规则。** 角色可以含糊、迂回、误解或说错话；文件则保持准确、稳定、可追溯。
5. **保留普通交流的分寸。** 不把所有分歧写成唇枪舌剑，也不把对方写成等待揭穿的反派。双方可以继续谈、暂时搁置或平静离开。

## 二、不同文本各写什么

| 文本类型 | 主要任务 | 应写 | 不应写 |
| --- | --- | --- | --- |
| 对方台词 | 回应当前问题，维护角色立场 | 具体答复、有限承诺、合理回避、真实情绪 | 教程、证据分析、编剧说明、超出权限的保证 |
| 玩家选项／主人公台词 | 把玩家的意图变成说得出口的话 | 一个明确问题、假设情形、条件或决定 | 抽象的「核对执行口径」「确认适用范围」 |
| 主人公内心活动 | 表现当下的感受、疑惑与理解变化 | 对一句话的直觉、新发现的联系、短暂犹豫 | 操作菜单、检索清单、标准答案、系统规则复述 |
| 文件与合同 | 构成可引用的书面依据 | 明确的条件、时间、责任与例外 | 为迎合口语化而删除关键限定 |
| 改稿通知 | 告知实际变化 | 改了哪些文件、哪项条件生效 | 「风险全部解除」或夸大结果的总结 |
| 结案文本 | 收束本次选择 | 承认已谈成、未谈成或主动放弃的部分 | 把签署等同于胜利，把拒签等同于失败 |

内心活动由界面自动加括号，Ink 原文使用 `# thought`；主人公说出口的话使用 `# player`。两类文字不得仅因排版而混用。

## 三、人物台词设计

### 3.1 先确定说话的人

每句台词写下之前，应能回答以下问题：

- 他此刻想让谈话往哪里走？
- 他实际上知道什么，哪些信息不会主动说？
- 他能答应什么，什么必须交给别人批准？
- 他在回答玩家的问题，还是把问题带到容易回答的地方？
- 这句话遮住姓名后，是否仍能凭用词与节奏认出他？

角色的口吻不是固定口头禅，而是其工作方式在对话中的表现。角色可以客气，也可以不耐烦；但不得因为剧情需要，突然替玩家分析自己的漏洞。

### 3.2 角色声线

**主人公**：认真但并非法律专家。先用具体生活情形提问，被绕开后再把问题拉回来。会犹豫、会误解，也会因谈妥一件事而松一口气。不使用全知视角，不提前知道尚未取得的材料内容。

**林悦（招聘 HR）**：熟悉招聘流程，希望尽快促成入职。语气温和，常用实际安排回应疑虑；涉及审批边界时承认自己做不了主。可以回避，不必句句带刺。

**许然（人事）**：希望流程顺利、少做例外。先回答容易确认的部分，用「都是一个体系」「按批次办」等说法淡化差异；被原文指出问题后承认具体事实，但不变成普法老师或证据教练。

**孟乔（内容组主管）**：说话直接，围绕任务、审稿、出勤与交接。能明确说出明天做什么、哪里不合格、记录在哪里；不替公司承诺工资或社保，也不为了显得友善而无条件站在玩家一边。

**郑衡（业务负责人）**：简洁、有决定感，先划清预算与权限。倾向用个人协调代替制度修改；面对有效证据时作有限让步，不绕长弯，也不突然变得亲切热络。

新角色沿用同一原则：先写目的、信息、权限和关系，再提炼说话习惯，不只靠称谓或口头禅区分。

### 3.3 把公文换成当事人语言

日常对白优先使用具体动词与生活后果。只有在角色确实需要引用文件时，才保留文件原词，并加上引号或明确出处。

| 避免直接说出口 | 可改为 |
| --- | --- |
| 请明确实际执行口径。 | 第二场要是取消了，我去的那一场还给钱吗？ |
| 这几天不转入应付。 | 这几天根本不给？ |
| 确认该岗位的适用范围。 | 凭什么我这个岗位也要受限？ |
| 从实际用工之日起办理。 | 从我上班那天开始办。 |
| 提供本人办理信息。 | 办完把回执给我。 |

并非所有短句都比长句好。涉及谈判条件时可以说完整，但必须能听出说话者的意图，不像条款摘要。

## 四、玩家选项与主人公台词

1. **一项选项只推进一个主要意图。** 问任务、问发钱条件和要求改稿不要挤在同一句里。
2. **优先写具体假设。** 使用「如果我干了五天再正常走」「如果第二场临时取消」等可回答的情形，避免抽象地问「如何处理特殊情形」。
3. **选项是主人公真实会说的话。** 删除选项标签式措辞，如「主体」「计付」「申报」「适用标准」；若确需使用，改成自然问句。
4. **保留不同策略。** 一组选项可以分别追问、索取文件、接受方案或暂缓，不应只是同一句话的三种礼貌程度。
5. **强硬不等于失智。** 玩家可以坚持底线、拒绝交易或离开，但不得为了制造僵局而突然提出与当前争议无关的要求。
6. **避免替玩家作过度判断。** 在证据尚未成立时，不直接让主人公断言对方违法、欺诈或一定撒谎。

## 五、主人公内心活动

### 5.1 内心活动的功能

内心活动表现认知变化，不是系统旁白。每次出现时，应当比上一刻多出一种真实反应：察觉异样、想起旧话、意识到混淆、形成疑问、承认误判或作出取舍。

优先写人物真正会想到的短句，不追求把规则解释完整。

| 场景 | 合适 | 不合适 |
| --- | --- | --- |
| 初次察觉 | 他说会处理，可单子上那条不改，将来不还是照它办？ | 当前承诺缺乏书面保障，需要核对现行文件。 |
| 发现两个概念不同 | 收据能发邮箱，不代表邮箱能报工资。 | 收据与申请入口的适用范围未对齐。 |
| 正常条款被问清 | 扣掉一小时午休，正好八小时。这里没多算。 | 本条不存在矛盾，建议结束当前话题。 |
| 收到改稿 | 总算有一家公司白纸黑字认下了。 | 相关责任主体已完成规范化调整。 |

### 5.2 异议阶段不得使用攻略口吻

`steps` 中的内心话只呈现主人公对当前说法的直觉、疑惑或初步联想，不指导玩家如何操作。

- 不写「先找／再找某文件」「选择某条原文」「补齐证据槽」「确认第几段」。
- 不提前列出完整证据组合，不直接公布标准答案。
- 不把界面操作或程序变量转译成角色心理。
- 可以在已有事实之间形成联想，但要保留玩家自行核对的余地。

**不推荐：**

> 先找离场流程：我的工作账号到底什么时候关？结算页也靠它登录。
>
> 再找离场指引：申请什么时候才开放？跟账号关闭的时间对一下。

**推荐：**

> 她说关账号不影响申请，可结算页不是也要用工作账号登录吗？这里总觉得不对。
>
> 账号离场当天就关了，申请却要等下一个工作日才开。等我能申请的时候，岂不是已经登不上了？

第二组文字只在玩家已经确认第一段原文后出现。想法应承接玩家实际取得的材料，不预设尚未提交的证据。

## 六、举证与错误反馈

### 6.1 提出异议

在对方明确说出可核对的主张后开启举证。主人公此时的内心活动负责表达「哪里听着不对」，不负责告诉玩家「怎样操作才对」。证据出处、数量和提交顺序由玩家从材料中判断。

### 6.2 举证成立

举证成立后，由主人公亲口完成正式反驳。正式反驳应包含：

1. 对方刚才承诺或主张了什么；
2. 引用的原文实际怎么写；
3. 两者在同一个具体情形下会造成什么不同后果；
4. 主人公希望怎样修改。

避免连续复述文件名和抽象术语。按「你说／纸上写／这意味着／请怎么改」组织，通常比逐条陈列证据更自然。

### 6.3 举证错误

错误提示只在玩家提交之后出现，顺序固定为：

> 对方针对引文作简短回应 → 主人公以 `# thought` 反思 → 游戏结算耐心并返回检查点。

**对方只回应，不提示答案。** 可以否认矛盾、指出引文与自己的说法一致、对无关材料表示疑惑；不得替玩家拆解证据链或指导检索。

**主人公的反思可以给出引导。** 应具体说明本次引用证明了什么、没有证明什么、混淆了哪两件事，或遗漏了哪个关键事实。可以建议重新核对某类材料，但不得只写「条件没有对齐」「证据不充分」。

**示例：**

```ink
=== wrong_account ===
人走关账号，这没问题。我又没说不让关。
对，关账号本身没错。真正不对的是关的时候，申请还没开。 # thought
-> END
```

对方没有被写成教程；引导来自主人公自己的理解变化。

## 七、事实、出处与规则边界

1. **先核引文，再写提示。** 文件名、时间、金额、条件、责任人和行为必须与 `documents` 中实际文字一致。不得把某项条件归到未记载它的文件中。
2. **不把相关当证明。** 排班能证明何时到场，不当然证明如何发钱；毕业日期能证明身份，不单独证明实际工作安排。
3. **不扩大改稿结果。** 谈成某项修改，只说明该项变化；不得让角色宣布所有风险已经消失。
4. **不乱改法律边界。** 文案负责人可以调整表达，但不得借润色改变证据成立条件、公司权限、法定责任或章节既定答案。
5. **不假设玩家路线。** 任何顺序进入、材料尚未取得、旧稿已替换、某项改稿已完成时，台词都应与当前事实一致。
6. **文件语言保持书面。** 口语化规则主要适用于对白、选项和内心活动；合同条款应准确、克制，并保留必要的限定条件。

## 八、改稿、沉默与结案

**改稿通知**：用一两句话说明「改了哪份文件、实际变成什么」。不需要复述谈判全过程，也不能代替玩家验收。主人公随后可有简短反应。

**沉默／暂缓**：表达还没想清楚或暂时不愿争，不使用「证据不足，退出举证」等系统语言。对方可以答应稍后再谈，不借机嘲讽玩家。

**耐心归零**：对方表达谈不拢、想暂停流程，不突然发布失败公告。主人公可以想再解释一次，也可以接受结束。

**签署**：承认实际签下的整套条件。全部修改、部分修改和原版签署应有不同收束，不把签字写成游戏通关奖励。

**拒签／离开**：允许失落，也保留主动性。不把拒签写成失败惩罚，不强迫主人公宣称自己作出了唯一正确选择。

## 九、交付前文案验收

### 台词与角色

- 遮住姓名朗读，能否辨认主要角色？
- 每句回应是否接得上上一句，是否答了玩家真正问的事？
- 是否出现角色替编剧解释系统、替玩家找证据的情况？
- 承诺是否符合角色权限，让步是否有利益上的理由？
- 连续朗读同一组选项，是否像一个人在该场景下能说的话？

### 内心活动与引导

- 异议阶段是否仍有「先找、再找、选择、补齐、提交第几段」等攻略措辞？
- 每段想法是否只使用主人公此刻已经知道的事实？
- 错误提示是否只出现在提交之后，并由主人公反思给出？
- 对方是否只回应而不教学？
- 提示是否指出了具体误区，而非「条件未对齐」式空话？
- 文件名称、时间与条件是否能在实际材料中找到？

### 连贯性与边界

- 正常条款是否允许问清后自然结束，而非硬造矛盾？
- 已取得材料、已有改稿和不同进入顺序下，台词是否仍然成立？
- 举证成立后的反驳是否说清冲突、后果和改法？
- 改稿通知、结案和复盘是否只描述实际发生的变化？
- 润色后是否仍保留原选项 ID、剧情路线和证据含义？

最终应完整试玩，而不只逐句阅读。重点观察玩家在何处误解、何处被过早提示，以及哪句话让他出戏。自动测试用于验证路线和规则，不能代替对语气与理解过程的真人验收。
