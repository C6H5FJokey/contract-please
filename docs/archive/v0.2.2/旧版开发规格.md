# 《来，签合同》开发规格 v0.2

交付单机单人网页版，含六份独立邀约、可重玩的签约与拒绝分支、本地存档和案例出处。玩法以 [旧版玩法设计](./旧版玩法设计.md) 为准。

## 规则与界面

左侧展示岗位、面试聊天、可索取的合同附件和已收材料。中间展示当前合同，点击条款设为追问对象，点击旁边的「引用」选择正文句子。右侧可按方向询问 HR，并在交涉记录和原文对照之间切换。窄屏顺序为材料、合同、交涉，已圈选引用时提供快速跳转。

追问对象为合同条款，方向为通用候选人问题。条款和方向共同决定具体答复与材料。原文对照表收集两到三段具体引用，诉求是解释差异、写清执行条件或修改条件。验证规则以可核对的原文片段为依据，每组必要事实允许多条同义或互补来源。单纯收到附件不会创建异议或修改合同。

书面变更每次生成累积版本，可同时改变正文及随附文件。原始资料与旧稿可回查，引用保留当时的句子和版本。签署使用现行稿。复盘按签署版本展示实际后果，并区别仅询问、写清原条件和修改条款。拒绝按现行稿展示假设后果。

## 数据与运行

静态 HTML、CSS 与 JavaScript 随项目交付。`data.js` 保存邀约、正文、附件、NPC 角色和真实来源。`comparisons.js` 定义通用追问、材料发放路线、可被引用的事实组合和部分改稿。`engine.js` 计算引用、交涉、版本和结局。`app.js` 负责交互与本机保存。

保存结构包含当前关卡、所收资料、在编辑的引用、对话、修订版本和复盘记录。v0.2 系列的存档可以继续载入。存储不可用时允许在当前页面继续。

## 开发与验收

1. 为每关编写一份雇主意图、真实案例、正文和相关附件。把证据切成可读的句子，确定同一件事的适用口径和可接受的替代引用。
2. 先用规则测试走通六关。验证不同追问可以交叉取得材料、无关原文不能改稿、存在合理的三段推理，以及正常金额差异得到正确解释。
3. 实现逐句引用、NPC 回应、正文与附件修订、旧版本查看、现行稿签署及拒绝。验证顺序改变时多个独立改稿仍能正确合并。
4. 在真实浏览器验证从追问到收到材料、选句、发出质疑、收到改稿、刷新恢复及签约复盘，检查窄屏布局。发布私密试玩与本地可运行版本。
5. 邀请玩家独立试玩。重点观察能否自己找到冲突原文，是否因为不理解适用条件而遗漏，是否看得出写清原条件与修改待遇的区别。根据记录修正文案和交互。

v0.2 的规则测试覆盖六关、重复追问、独立修订、正常合同和存档恢复。后续玩法扩展以试玩反馈为依据。
