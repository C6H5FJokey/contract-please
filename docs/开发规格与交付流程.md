# 开发规格与交付流程

这一版先交付一个完整的泊石展务剧本和独立的交涉框架。新剧本写法见 [编剧指南](交涉框架与编剧指南.md)，玩法以 [交涉版规格](来，签合同-玩法设计.md) 为准。

v0.4 的迁移范围、实现规格和验收条件见 [Ink 与 TypeScript 重构计划](Ink%20与%20TypeScript%20重构计划.md)。

1. **取材与定题。** 确认公开案例支持的事实，记录虚构调整和取材链接。从具体条款的条件差异出发，列出双方目的、材料和权限。
2. **材料与对照。** 写好原合同和各附件，标明哪几句可以证明矛盾、哪几句只是相关。提前写出谈成后会发的改稿。
3. **对白与分支。** 先走一条完整路径，再补没有材料时的沉默、合理追问、失败、僵局及签或不签的分支。用不同话题和权限约束写出每份合同自己的节奏。
4. **试玩与检查。** 在仓库根目录安装依赖后运行 `npm test`，再运行 `npm start`。浏览器检查开场、打字与跳过、附件阅读停顿、手机圈选、提交记录的恢复、续关和结案。实际走完后根据玩家在哪一句理解错了打磨台词。
5. **发布。** 按下节确认本次发布的章节，运行 `npm run build` 生成静态 `dist/`。仓库 Pages 选择 GitHub Actions 后，推送到 `main` 会触发安装、测试、构建和部署。版本标签用于标记提交，推送标签不会触发 Pages 部署。

## 章节发布与验收

[章节目录](../content/chapters.ts) 记录每章的发布状态和首页顺序。

| 状态 | 本地试玩 `npm start` | 正式构建 `npm run build` |
| --- | --- | --- |
| `candidate` | 在章节首页展示，按顺序解锁 | 不打包，首页也不显示锁定卡片 |
| `released` | 在章节首页展示，按顺序解锁 | 打包并在首页展示，按顺序解锁 |
| `demo` | 用章节链接直接进入测试场景 | 不打包 |

发布某章时，将它设为 `released`，并用正式构建产物核对首页列出了本次发布的全部章节。先用无进度的浏览器确认后续章节显示为尚未解锁，再完成前序章节结案，确认新章节可以从首页进入。部署成功后，在 Pages 上复核章节列表与进章行为。
